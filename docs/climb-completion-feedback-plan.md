## Problem Statement

현재 등반 완료 버튼은 클릭 직후 색상, 문구, 아이콘만 바뀌어 저장이 이루어졌다는 손맛과 확신이 약하다. 또한 같은 버튼을 다시 누르면 완료가 곧바로 해제되어, 사용자가 실수로 자신의 등반 기록을 지울 수 있다.

이번 변경의 목적은 완료 저장 순간을 짧지만 기억에 남는 피드백으로 만들고, 완료 해제는 기록 관리 맥락인 마이페이지에서만 가능하게 하는 것이다.

## Product Decision

- 지도와 산 상세의 완료 버튼은 `미완료 → 저장 중 → 완료`의 단방향 상태를 갖는다.
- 완료 상태에서는 다시 눌러도 해제되지 않는다.
- 완료 해제는 마이페이지의 기존 `완료 해제` 동작에서만 제공한다.
- 제품 의미는 “이 산을 완료했는가”라는 산별 이진 상태다. 같은 산의 여러 DB 행은 레거시 또는 중복 데이터로 취급하며 개별 등반 이력으로 노출하지 않는다.
- 공개 서비스의 여러 탭·기기 동시 요청도 이진 상태를 지키도록 DB에 `(user_id, mountain_id)` unique 제약을 둔다.
- 성공 애니메이션은 실제 Supabase 저장이 성공한 뒤 시작한다.
- 이번 범위는 마이크로 인터랙션과 해제 경로 정리다. 보상 시스템이나 데이터 모델 변경으로 확장하지 않는다.

## What Makes This Cool

버튼을 누르면 표면이 살짝 눌렸다가 아이콘 자리에서 원형 라인이 소용돌이처럼 회전한다. 저장이 끝나는 순간 원이 수축한 뒤 탄성 있게 튀어 오르고, 체크가 `0.4 → 1.15 → 1` 배율로 통통 튀며 안착한다. 버튼의 크기와 위치는 유지되어 화면은 안정적이지만, 손끝에는 쫀득한 반응이 남는다.

## Constraints

- `DESIGN.md`의 색상, 최소 터치 영역, 가독성 기준을 따른다.
- 완료색은 디자인 시스템의 Primary Green `#245C46`을 사용한다.
- 40–70세 사용자도 상태를 쉽게 이해할 수 있도록 색상만으로 성공을 표현하지 않고 체크와 문구를 함께 사용한다.
- 버튼 폭이나 레이아웃은 애니메이션 중 변하지 않는다.
- 사운드, 진동, 폭죽, 컨페티, 모달, 배지, 연속 등반 보상은 추가하지 않는다.
- 새 애니메이션 패키지는 설치하지 않는다. React, CSS keyframes, 인라인 SVG로 구현한다.
- `prefers-reduced-motion: reduce`에서는 회전과 스프링을 생략하고 저장 성공 후 즉시 완료 상태를 표시한다.
- DB 마이그레이션은 기존 중복 행을 먼저 정리한 뒤 unique 제약을 추가해야 하며, 마이그레이션 적용 전에 현재 DB 백업을 확인한다.

## Motion Specification

### Default motion

| 구간 | 시점 | 동작 |
|---|---:|---|
| Press | 0–100ms | 버튼 콘텐츠가 `translateY(1px)`과 약 `scaleY(0.95)`로 살짝 눌린다. 버튼 외곽 크기는 유지한다. |
| Saving | 응답 대기 | 콘텐츠는 원위치로 돌아오고 아이콘 영역의 원형 라인이 회전한다. 버튼은 disabled 상태로 중복 클릭을 막는다. |
| Success anticipation | 0–80ms | 회전 원이 약 `0.88` 배율로 짧게 수축한다. |
| Check pop | 80–430ms | 원이 `0.88 → 1.08 → 0.98 → 1`, 체크가 `0.4 → 1.15 → 1`로 등장한다. 체크는 약 `-8deg → 0deg`로 정렬한다. |
| Settle | 430–700ms | 배경과 문구가 완료 상태로 안정되고 모든 transform이 제거된다. |

구현 시 수치는 시작값이다. 실제 기기에서 버튼이 고무처럼 늘어져 보이면 overshoot를 줄이고, 단순 fade처럼 느껴지면 체크의 최대 배율을 높인다. 전체 성공 전환은 약 650–800ms 안에 끝나야 한다.

### Timing rules

- 네트워크 응답 전에는 체크를 노출하지 않는다.
- 매우 빠른 응답에서도 저장 중 상태를 인지할 수 있도록 회전 상태의 최소 노출 시간은 250ms로 둔다. 단, reduced-motion 환경에서는 이 최소 시간을 적용하지 않는다.
- 느린 요청에서는 회전을 계속하되 버튼 문구를 불필요하게 반복 변경하지 않는다.
- 실패 시 성공 모션을 실행하지 않고 미완료 상태로 복구한다.
- `completion-check-pop` 애니메이션은 성공 SVG를 감싸는 단일 wrapper 자체에 적용하고 그 wrapper에 `onAnimationEnd`를 연결한다. 원과 체크 path의 그리기 애니메이션은 자식에서 실행한다. wrapper 이벤트는 `event.currentTarget === event.target`과 animation name을 모두 확인한 뒤 완료 상태로 정리한다.
- 이벤트가 누락되면 `celebrating` 진입 900ms 후 fallback 타이머가 완료 상태로 정리한다. 컴포넌트 unmount, 대상 mountain 변경, 새 상태 전환 시 타이머를 취소한다.

### Reduced motion

- 누름 변형, 회전, 수축, overshoot를 모두 생략한다.
- 저장 중에는 정적인 진행 표시와 disabled 상태를 사용한다.
- 성공 시 배경, 체크, `등반 완료` 문구를 즉시 표시한다.

## Accessibility and Copy

- 미완료: 화면 문구 `등반 완료`, 접근성 이름 `등반 완료로 기록`.
- 저장 중: 화면 문구 `저장 중`, 접근성 이름 `등반 완료 저장 중`. 버튼의 최소 폭을 완료 문구 기준으로 고정하고 `aria-busy="true"`와 disabled를 사용한다.
- 완료: 화면 문구 `등반 완료`, 접근성 이름 `등반 완료됨`. 해제 가능하다는 인상을 주는 문구나 hover 상태를 사용하지 않는다.
- 저장 시작은 버튼의 `저장 중` 문구와 `aria-busy`로 표현한다. 성공 시 기존 App의 `role="status"` toast에 `등반 완료로 기록했어요.`를 표시하고, 실패 시 `getCompletionErrorMessage`가 반환한 기존 오류 문구를 같은 영역에 표시한다.
- 완료 상태에서도 터치 영역은 최소 44px을 유지한다.
- 완료 상태는 실제 `<button disabled>`로 렌더한다. 키보드 포커스와 클릭 대상에서 제외하고 `cursor: default`, `opacity: 1`로 표시하며 hover/active 변형은 제거한다.

## State Machine

```text
               click
  INCOMPLETE -----------> SAVING
      ^                      |
      |                      | save failure
      +----------------------+
                             |
                             | save success
                             v
                         CELEBRATING
                             |
                             | motion end / reduced motion
                             v
                          COMPLETED

  COMPLETED -- map/detail click --> COMPLETED
  COMPLETED -- My Page remove ----> INCOMPLETE (after shared data refresh)
```

영속 완료 여부는 `completionRecords`에 해당 산의 레코드가 하나 이상 존재하는지로 판단하고, 기존 `completedIds`를 source of truth로 유지한다. 마이페이지의 기존 삭제 서비스는 `.eq('user_id', ...).eq('mountain_id', ...)`로 해당 산의 모든 행을 이미 삭제하므로 성공 후 `INCOMPLETE`가 된다. 이후 사용자가 다시 완료하면 새 행 하나가 생성되지만, 이는 새 이진 완료 상태이며 과거 반복 등반 이력을 보존한다는 의미가 아니다.

버튼 인스턴스의 로컬 애니메이션 상태는 별도로 관리한다.

```text
IDLE_INCOMPLETE -- click --> SAVING
SAVING -- callback false --> IDLE_INCOMPLETE
SAVING -- callback true + min delay --> CELEBRATING
CELEBRATING -- guarded animationend / 900ms fallback --> IDLE_COMPLETED
IDLE_COMPLETED -- click --> IDLE_COMPLETED
```

렌더 우선순위는 `saving > celebrating > persistent completed > incomplete`다. 따라서 App이 성공 직후 `completedIds`를 갱신해도 최소 회전 시간과 체크 모션이 생략되지 않는다. 클릭한 버튼 인스턴스만 성공 모션을 실행하며, 같은 산을 표시하는 다른 인스턴스는 공유 영속 상태를 통해 정적인 완료 상태로 갱신된다.

## Architecture

App completionRecords / completedIds
              |

      |                 |
      v                 v

### Component boundary

- 지도 상세 패널과 `MountainDetailPage`에 중복된 버튼 마크업을 공유 `CompletionButton`으로 추출한다.
- 공유 컴포넌트의 핵심 계약은 `completionKey: string`, `isCompleted: boolean`, `isPending: boolean`, `onComplete: () => Promise<boolean>`이다. `true`는 서버 저장과 App 상태 갱신이 모두 성공했음을 뜻한다. `false`는 로그인/데이터 준비 검사, 저장 실패, 또는 동일 산 요청이 이미 진행 중임을 뜻한다.
- 공유 컴포넌트는 `idle | saving | celebrating` 로컬 상태, 최소 회전 시간, guarded `animationend`, fallback 타이머와 cleanup을 책임진다. 원시 오류를 해석하거나 toast를 직접 만들지 않는다.
- `completionKey`가 바뀌거나 컴포넌트가 unmount되면 request token을 증가시키고 타이머를 정리한다. Promise와 대기가 끝날 때 token이 현재 요청과 다르면 로컬 상태를 변경하지 않는다. 호출부에서도 `key={mountain.id}`를 사용해 산 교체 시 인스턴스를 분리한다.
- `App`은 Supabase 저장, 오류 메시지, 성공 메시지와 영속 `completionRecords` 갱신을 책임진다. 저장은 pessimistic 정책으로 고정하여 INSERT 성공 후에만 레코드를 추가한다. 동일 산 요청 차단은 ref-backed `Set<string>`을 동기적으로 검사·등록하고 `finally`에서 무조건 제거한다. React state는 버튼의 `isPending` 렌더링에만 사용한다.
- 마이페이지의 삭제 서비스와 UI는 그대로 유지한다.

## Data Flow

```text
click
  -> CompletionButton: saving, startTime 기록
  -> onComplete()
       -> App의 로그인/데이터 준비 검사
       -> ref-backed Set에 mountain id가 있으면 toast 없이 false 반환
       -> mountain id를 Set에 동기 등록
       -> Supabase UPSERT onConflict(user_id,mountain_id)
            success -> DB가 반환한 id/completed_at으로 completionRecords 반영 + 성공 toast + true 반환
            failure -> 오류 toast + false 반환
       -> finally에서 mountain id를 Set과 pending 렌더 state에서 제거
  -> false: 즉시 idle/incomplete 복귀
  -> true:
       reduced motion -> 즉시 idle/completed
       default motion -> max(0, 250ms - elapsed) 대기 -> celebrating
  -> guarded animationend 또는 900ms fallback -> idle/completed
```

저장 성공을 애니메이션의 사실 근거로 삼기 위해 현재의 즉시 완료 optimistic 표시를 pessimistic 갱신으로 바꾼다. upsert payload는 `user_id`, `mountain_id`만 보내고 DB의 기존/default `completed_at`을 사용하며, `.select('id,mountain_id,completed_at').single()` 결과를 App 상태에 넣는다. 버튼 로컬 상태가 영속 완료 상태보다 높은 렌더 우선순위를 가지므로 빠른 응답에서도 성공 모션이 건너뛰어지지 않는다. 버튼 자체의 `saving` 상태와 App의 ref-backed mountain id in-flight guard는 같은 탭의 즉각적인 중복 요청을 막고, DB unique 제약과 upsert는 여러 탭·기기의 동시 요청을 하나의 행으로 수렴시킨다.

## Existing Code Reuse

- `src/App.tsx`의 `completionRecords`, `completedIds`, 로그인/데이터 준비 상태 검사와 Supabase insert를 재사용한다.
- `src/App.tsx`의 지도 상세 패널 완료 버튼과 `src/components/MountainDetailPage.tsx`의 완료 버튼을 공유 컴포넌트로 합친다.
- `src/components/MyPage.tsx`의 `removeCompleted` 흐름과 `src/services/myPage.ts`의 `deleteCompletedMountain`을 그대로 사용한다.
- `src/services/completionErrors.ts`의 저장 오류 메시지 변환을 재사용한다.
- 기존 UUID `id` 기본키, RLS 정책, 완료 조회·삭제 흐름은 유지한다.
- 새 마이그레이션은 `(user_id, mountain_id)`별 `completed_at desc, id desc` 기준 첫 행만 남기고 중복 행을 삭제한 뒤 `completed_mountains_user_mountain_key` unique 제약을 추가한다.
- 저장은 Supabase의 `upsert(..., { onConflict: 'user_id,mountain_id' })`와 반환 행 조회를 사용한다. 별도 서버 함수나 조회 후 insert 흐름은 만들지 않는다.

## Error and Rescue Registry

| Method/codepath | Failure | Rescued | Rescue action | User impact |
|---|---|---|---|---|
| completion click | 비로그인 | Yes | 저장 요청 없이 로그인 안내 | 기록되지 않음 |
| completion click | 완료 데이터 미로딩 | Yes | 요청 차단 및 재시도 안내 | 기록되지 않음 |
| completion insert | 네트워크/Supabase 오류 | Yes | pending 해제, 미완료 복구, 기존 오류 문구 표시 | 다시 시도 가능 |
| completion insert | 빠른 연속 클릭 | Yes | mountain id 기준 pending lock | 중복 요청 없음 |
| completion upsert | 여러 탭·기기의 동시 요청 | Yes | DB unique 제약과 atomic on-conflict 처리 | 하나의 완료 상태로 수렴 |
| completion upsert | unique 마이그레이션 미적용 | Yes | 저장 오류 처리, 배포 체크에서 constraint 존재 확인 | 오류 메시지 후 재시도 가능 |
| success animation | `animationend` 누락 | Yes | wrapper의 guarded event와 900ms fallback, unmount/key-change cleanup | 완료 상태 유지 |
| MyPage delete | 네트워크/Supabase 오류 | Yes | 기존 목록 복구와 오류 안내 유지 | 기록 유지 |
| MyPage delete | 다른 화면의 완료 상태가 남음 | Yes | 성공 후 기존 `onCompletionRecordsChange`로 App의 공유 레코드에서 해당 산의 모든 항목 제거 | 즉시 미완료로 동기화 |

## Test Plan

### Unit/component tests

- 미완료 버튼 클릭 시 insert가 한 번만 호출되고 저장 중 disabled가 된다.
- 저장 성공 전에는 체크 성공 상태가 노출되지 않는다.
- 저장 성공 후 `celebrating`을 거쳐 완료 상태로 수렴한다.
- 저장 실패 시 미완료 상태로 돌아가고 오류 문구를 표시한다.
- 빠른 이중 클릭에도 insert는 한 번만 호출된다.
- 같은 산을 가리키는 두 버튼 인스턴스를 같은 tick에 연속 클릭해도 ref-backed in-flight guard로 insert는 한 번만 호출되고 guard는 성공·실패·예외 모두에서 해제된다.
- 두 클라이언트가 동시에 upsert해도 `(user_id, mountain_id)` 행은 하나이고 두 요청 모두 완료 상태로 수렴한다.
- 기존 중복 fixture를 마이그레이션 로직에 적용하면 최신 `completed_at` 행 하나만 남는다.
- 완료 상태의 지도/상세 버튼은 disabled이며 insert와 delete를 모두 호출하지 않는다.
- 완료 상태 접근성 이름에 `해제`가 포함되지 않는다.
- 비로그인 및 완료 데이터 미로딩 상태에서는 insert 없이 기존 안내가 `role="status"`에 표시된다.
- 저장 중 `저장 중`, 성공 시 `등반 완료로 기록했어요.`, 실패 시 변환된 오류 문구가 각각 접근 가능한 상태로 노출된다.
- reduced-motion 조건에서는 회전/스프링 클래스가 비활성화되고 완료 상태는 정상 반영된다.
- 관련 없는/bubbled `animationend`는 무시하고, 정상 이벤트 또는 900ms fallback 이후 완료 상태에 머문다.
- 저장 중 산이 교체되거나 컴포넌트가 unmount되면 오래된 Promise 결과와 타이머가 새 버튼 상태를 변경하지 않는다.
- 마이페이지의 `완료 해제`는 기존과 같이 delete를 호출하고 목록을 갱신한다.
- 동일 산의 레코드가 여러 개인 기존 데이터에서 마이페이지 해제 시 모든 행을 삭제하고 App의 모든 해당 레코드를 제거한다.

### Visual/interaction QA

- 360px 모바일, 데스크톱 상세 패널에서 버튼 폭과 주변 레이아웃이 움직이지 않는다.
- 실제 느린 네트워크에서 회전이 끊기지 않고 실패 시 체크가 나타나지 않는다.
- 실제 빠른 네트워크에서 회전이 깜박임처럼 보이지 않는다.
- 체크가 과도하게 커지거나 고무처럼 늘어지지 않고 한 번만 튄다.
- 키보드와 스크린 리더로 저장 중/성공/실패 상태를 구분할 수 있다.

## Implementation Sequence

1. 기존 중복 데이터를 최신 행 하나로 정리하고 `(user_id, mountain_id)` unique 제약을 추가하는 Supabase 마이그레이션과 검증 SQL을 만든다.
2. `CompletionButton`의 상태 계약과 SVG/CSS 모션을 만든다.
3. `App.toggleCompleted`를 DB 반환 행을 사용하는 `completeMountain(): Promise<boolean>` 단방향 upsert 흐름으로 바꾸고 mountain id 기준 in-flight guard를 추가한다.
4. 지도 상세 패널과 `MountainDetailPage`의 버튼을 공유 컴포넌트로 교체한다.
5. 상세 화면의 `등반완료 해제` 문구와 delete 분기를 제거한다.
6. 기존 App 테스트의 상세 해제 기대값을 단방향 완료 기대값으로 변경하고 상태/실패/동일 탭·여러 클라이언트 중복 요청 테스트를 추가한다.
7. 마이페이지 해제 회귀 테스트와 모바일·reduced-motion 수동 QA를 수행한다.

## Rollback

```text
animation regression?
  |-- CSS only issue --> motion styles 비활성화, 단방향 완료 정책 유지
  |-- state issue ----> shared button 이전 렌더로 복귀, save guard 유지
  |-- save regression -> 이전 insert handler로 임시 롤백 가능, unique 제약은 유지
  |-- migration issue -> 배포 중단, 백업/검증 결과 확인 후 중복 정리와 제약 적용 재시도
```

unique 제약은 확정된 이진 완료 모델의 데이터 무결성 규칙이므로 프런트엔드 롤백과 함께 제거하지 않는다. 제약 추가 전에 삭제되는 중복 행은 백업 또는 별도 audit 결과로 복구 가능해야 한다.

## Success Criteria

- 버튼 클릭 후 저장 중, 성공, 완료 상태가 시각·접근성 정보로 구분된다.
- 성공 체크는 서버 저장 성공 후에만 나타난다.
- 완료 버튼의 전체 레이아웃은 모션 중 이동하지 않는다.
- 빠른 연속 클릭으로 중복 insert가 발생하지 않는다.
- 여러 탭·기기의 동시 완료 요청도 DB 행 하나로 수렴한다.
- 지도와 상세에서 완료 해제가 불가능하다.
- 마이페이지에서는 완료 해제가 계속 가능하다.
- reduced-motion 사용자는 의미 손실 없이 즉시 완료 상태를 확인한다.
- 관련 자동화 테스트와 production build가 통과한다.

## NOT in Scope

- 컨페티, 사운드, 햅틱: 단순 성공 피드백의 범위를 넘고 사용자 환경별 편차가 크다.
- 배지, 스트릭, 연속 등반 보상: 별도 제품 가설과 데이터 설계가 필요하다.
- 버튼을 원형으로 축소: 레이아웃 이동과 문구 가독성 저하를 유발한다.
- 애니메이션 라이브러리 도입: 이 모션에 필요한 범위보다 의존성 비용이 크다.
- 개별 등반 이력 모델: 이번 이진 완료 UX와 별개의 데이터 재설계가 필요하다.
- 마이페이지 UX 재설계: 기존 해제 흐름을 그대로 재사용한다.
- 앱 전체 성공 애니메이션 시스템: 재사용 가능성은 있으나 이번 기능을 위해 선제 구축하지 않는다.
